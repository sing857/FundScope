# FundScope

**看市场，也看自己。**

做这个项目的初衷很简单：我想弄清楚，一只基金过去究竟经历了什么。

净值曲线记录着涨跌，收益率呈现着结果，而波动与回撤则让那些容易被收益数字掩盖的风险逐渐显现出来。比起只看一段时间赚了多少，我更想知道，这份收益是在什么样的波动中取得的，又曾经承受过多大的下跌。

随着项目的发展，FundScope 逐渐从基金历史表现分析工具，扩展为包含上市公司财务研究能力的金融数据分析项目。

FundScope 基于 Python 构建，使用公开金融数据，尝试将数据获取、指标计算、风险观察和分析结果展示整理成一套可追溯的研究流程。项目仍在持续开发中，重点是让分析过程更加清晰，而不是直接提供投资结论。

## 当前功能

### 基金分析网页

输入基金代码后，可以获取历史净值并查看相关分析结果：

- 区间收益率、年化收益率
- 年化波动率、下行波动率
- 最大回撤及回撤区间、恢复情况
- 夏普比率、索提诺比率、卡玛比率
- 基金历史质量评分及评分构成
- 历史净值曲线、净值明细和数据质量信息

历史质量评分属于基于既定规则的初步评价，不代表未来表现，也不构成买入或卖出建议。

### 上市公司企业研究页面

企业研究功能已经接入 Streamlit，可以通过网页查询上市公司并查看相关分析结果。

目前主要包括：

**1. 企业概览与市场规模**

展示企业基础信息及相关市场信息。

**2. 经营与成长**

观察企业营业收入、利润及相关指标的历史变化，并提供季度趋势分析。

**3. 财务健康**

围绕资产负债结构、短期偿债能力、现金储备和经营现金流等方面展开分析。

**4. 风险与核查**

根据既定规则识别值得进一步关注的财务信号，并提供后续核查方向。

**5. 数据质量**

检查财务报表字段、报告期匹配、数据覆盖情况及其他数据质量问题。

企业分析不采用简单的综合评分代替判断。数据结果、指标解释和风险推断应当相互区分。

规则触发不等于企业存在造假、违规或经营失败；没有触发规则，也不意味着企业不存在风险。

### 尚未实现的功能

页面中的假设与反向检验区域目前只是功能入口，分析引擎尚未接入。

项目不会将该入口产生的内容描述为已经完成的回测或智能分析结果。

## 技术栈

- Python：项目主要开发语言
- AKShare：获取公开金融数据

- Streamlit：网页交互与数据展示
- Matplotlib、Altair：数据可视化
- pytest：自动化测试

## 环境与安装

项目当前在 Windows 环境、Python 3.14.3 下完成开发和测试。其他 Python 版本及操作系统尚未全面验证。

建议在项目目录中创建独立虚拟环境：

```powershell
python -m venv .venv
```

激活虚拟环境：

```powershell
.\.venv\Scripts\Activate.ps1
```

如果 PowerShell 的执行策略阻止激活脚本，也可以不激活环境，直接使用虚拟环境中的 Python 可执行文件运行后续命令。

安装运行依赖：

```powershell
python -m pip install -r requirements.txt
```

启动网页：

```powershell
python -m streamlit run app.py
```

启动成功后，在浏览器中打开终端显示的本地地址。

## 数据与计算说明

基金历史净值及相关公开金融数据通过 AKShare 等数据接口获取。数据接口的可用性取决于网络环境和上游服务，数据可能存在延迟、缺失或口径差异。

当前基金分析使用项目所获取的净值数据进行计算。基金分红、复权方式、数据完整性和年化计算口径等因素都可能影响结果。使用分析结果前，应结合原始数据和基金产品资料进行核对。

企业财务分析依赖公开财务报表数据。

利润表和现金流量表中的部分指标属于报告期累计值，资产负债表指标则反映报告期末的时点情况。进行季度趋势分析时，需要注意累计值与单季度数据之间的转换口径。

财务指标和异常提示属于规则化分析工具，不能替代对企业经营模式、行业特征、会计政策及其他定性因素的全面调查。通用规则也不一定适用于银行、保险、证券等金融机构。

## 后续方向

项目会优先完善现有数据校验、计算口径和分析逻辑，再逐步推进基金比较、业绩基准及更系统的风险分析。

企业研究方面，将继续完善财务指标解释、风险核查逻辑和数据质量控制，让分析结果更加清晰、可靠和可追溯。

对于投资而言，数字能够帮助我们理解过去，却无法替我们确定未来。这个项目所做的，是尽可能把过去的表现整理清楚，让判断有据可依。
